■ 4. KISA 온디바이스 딥페이크 탐지 SDK 과제
- 역할·기간: SDK 설계·개발 메인 / 모델 경량화 서브 · 3사 협업 · 2026.04 ~ 2026.10
- 기술: Kotlin · Swift · C++ · NDK/JNI · ONNX Runtime · NNAPI · XNNPACK · CoreML · CMake
- 개요: 서버 없이 Android/iOS 단말에서 딥페이크를 탐지하는 SDK. Android/iOS가 같은 전처리·추론 경로를 쓰게 하고, SDK 재배포 없이 모델만 교체할 수 있도록 C++ 공통 코어 기반으로 설계·개발.
- 주요 경험
· 크로스플랫폼 · Android + iOS — Kotlin/Swift 인터페이스 → C++ 공통 코어 → ONNX Runtime 추론 계층으로 분리. 탐지·전처리·후처리를 C++에서 공통화.
· 모델 교체·배포 — 설정 + 암호화 모델 + 서명을 패키지 하나로 분리 → SDK 재배포 없이 모델 교체. mVaccine 서명 형식 계승 + AES-256-GCM 봉투 암호화 자체 설계, 전체 SHA-256 검증 후 스테이징 교체. 검증 실패 시 기존 설치본 유지, 로드 실패 시 재설치 복구.
· 실앱 OTA 검증 — 고객사 배포 전 사내 앱(라온 모바일 시큐리티)에 연동해 모델 교체 검증. 재시작·오프라인에서도 업데이트된 모델 유지 확인.
· 모델 최초 설치 · 14.8초 → 0.3초 — 설치 전 검증과 로드에서 두 번 하던 복호화를 한 번으로, OTA 모델 검증은 유지.
· 모델 단위 API 재설계 — 전역 설정으로는 다중 모델 불가 → 모델 1개 = 인스턴스 1개 구조. 전·후처리 Builder 주입, 갱신은 앱에서 제어.
· 단말·런타임 호환성 — NNAPI 벤더 드라이버 크래시 확인 → Android는 XNNPACK 우선. iOS는 CoreML 우선 구성. ARM32 SIGBUS는 ORT 그래프 최적화 단계까지 추적해 32비트에서 문제 최적화 단계만 비활성화. Android 15+ 16KB 페이지 크기 대응.
· 출력 재현·검증 — 협력사 참조 구현 대비 출력 오차 ≤ 1e-5(얼굴 검출 박스 고정). C++ 회귀 257건 · 실단말 테스트 70+건 · iOS XCTest 130+건.
· 단말 간 판정 차이 해결 — 단말마다 오디오 디코딩 결과가 달라짐 → MediaParser 전환, 3개 단말의 오디오 데이터(PCM) 일치 확인.
· 음성·영상 전처리 공통화 — 멜 스펙트로그램·컬러맵·리샘플링·몽타주 전처리를 Python에서 C++ 공통 코어로 이식.
